# Hero with a full-cover video background

Date: 2026-10-30
Status: approved design, pending implementation plan

## Problem

The hero block is a two-column opener: the heading, subheading and CTA beside a CMS image. Editors want the hero to
carry a video that fills it edge to edge, with the text on top.

## Goal

The hero is one full-cover design. Its background is the block's video when one is set, otherwise its image, otherwise
the plain page background. Editors pick the video from the Umbraco media library.

Success criteria:

- An editor adds a video (MP4, WebM or Ogg from the media library) to a hero block; the published page shows it
  muted, looping and autoplaying behind the hero text, across the full viewport width.
- The image is the video's poster and the fallback: no video set, video not playable, or `prefers-reduced-motion`.
- A hero with neither video nor image still renders cleanly (text on the page background).
- Existing content keeps working without edits: heroes without a video show their image as the cover.
- No horizontal page scroll at any width; text stays readable (contrast) over any media.
- Core code still works with an empty CMS; unknown or unusable media never fails a page.

## Decisions

- **Source: Umbraco media library** (the built-in Video media type `umbracoMediaVideo`), not a URL field.
- **No video: image as cover**, so there is one hero design; the image doubles as poster and fallback.
- **Width: full viewport**, breaking out of the page's `max-w-6xl` column; the text stays aligned to that column.

## Design

### CMS (`src/Cms/uSync/v18`)

- New data type **Video Media Picker** (`Umbraco.MediaPicker3`, single item, filter = the `umbracoMediaVideo` media
  type `f6c515bb-653c-4bdc-821c-987729ebe327`), modelled on `DataTypes/ImageMediaPicker.config`.
- `ContentTypes/heroblock.config`: new optional property `video` ("Video", description: plays muted and looping
  behind the hero; the image is its poster and fallback) using that data type, next to `image`.
- Existing installs import the schema in the backoffice (Settings > uSync > Import), then restart the cms (as for every
  schema change). The demo seeder is unchanged: the demo heroes keep their images.

### Delivery API models

Refresh `src/Api/Content/Umbraco/delivery-api.json` from the running CMS and regenerate `DeliveryApiModels.g.cs`
(`node scripts/gen-delivery-api.mjs --from http://localhost:<cms http port>`); the hero's element properties gain
`Video` (`ApiMediaWithCropsModel[]?`).

### API

- Contract: `public sealed record Video(string Url, string MimeType);` in `Contracts/` (next to `Image`), and
  `HeroBlock(string Heading, string? Subheading, Image? Image, Link? Cta, Video? Video)` (new last parameter).
- `DeliveryApiMapper`: `GetVideo(ApiMediaWithCropsModel[]? media)` returns the first item if it is
  `UmbracoMediaVideoMediaWithCropsModel` with a non-empty URL and a known extension, with the URL made absolute like
  images (`ToAbsoluteUrl`); MIME type by extension, case-insensitive: `mp4` → `video/mp4`, `webm` → `video/webm`,
  `ogv`/`ogg` → `video/ogg`. Anything else (another media type, no URL, other extension) → `null`, never an error.
- OpenAPI (`src/Api/openapi/Api.json`) is regenerated by the build; `Video` appears as a schema and `HeroBlock.video`
  as nullable.

### Web (`src/Web`)

`npm run gen:api`, export `Video` from `src/lib/api/client.ts`, and rewrite `components/blocks/Hero.astro`:

- **Layout**: the section spans the viewport (`w-screen` breakout from the `max-w-6xl` main column) with a minimum
  height (about 70vh on large screens, less on small); inner content uses the same `max-w-6xl px-4 sm:px-6` column as
  the page. When the hero is the first block (`first`), it cancels the main element's top padding so it sits directly
  under the header. `body` gets `overflow-x: clip` so the breakout (100vw includes the scrollbar) never scrolls
  sideways.
- **Background** (absolutely positioned, `object-cover`, behind the content):
  - video set: `<video autoplay muted loop playsinline preload="metadata" aria-hidden="true" tabindex="-1">` with one
    `<source src type>` and `poster` = the image's largest rendition (or none); hidden under `prefers-reduced-motion`
    (CSS `motion-reduce:hidden`), where the image layer shows instead;
  - image set (always rendered under the video when present): `ResponsiveImage` with `sizes="100vw"`, the focal point
    as object position, `loading="eager"` when `first`;
  - neither: no background layer.
- **Overlay and text**: when there is a video or image, a dark overlay (gradient from the text side) sits between
  media and text, and heading, subheading and CTA switch to light text with the subheading at reduced opacity. The CTA
  stays the `signal` button. Without media the hero uses today's text colours. Fonts follow the site rules (heading and
  subheading serif).
- Remove the old two-column layout and its image panel.

### Docs

README: content model row for `heroBlock` gains `video`; the API section mentions `HeroBlock.video` (`Video` with
`url` and `mimeType`).

## Testing

- `DeliveryApiMapperTests`: hero with a video maps `Video` with absolute URL and MIME type; a non-video media item and
  an unknown extension map to `null`; a hero without video maps `Video = null` and keeps its image.
- `ContractSerializationTests`: `HeroBlock` with a `Video` round-trips.
- `dotnet build AspireTest.slnx && dotnet test AspireTest.slnx`; the Delivery API models and OpenAPI are regenerated
  (CI checks staleness); `npm run check`.
- Running stack: after the uSync import, the backoffice hero block shows the Video picker. Home screenshots before and
  after (image cover, full width, no horizontal scroll at 1280px and 375px). With a short test MP4 (generated with
  ffmpeg) uploaded to the media library and picked on the home hero: the video plays muted and looping; with
  `prefers-reduced-motion: reduce` emulated the image shows instead. Uploading needs the user (backoffice sign-in).

## Out of scope

- External video URLs, captions/subtitles, play/pause controls (the video is decorative and muted).
- Multiple sources per video (one file; editors pick the format).
- Seeding a demo video.
- Video anywhere other than the hero block.
